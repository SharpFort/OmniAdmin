# 4. 菜单数据源后端模式切换说明

> **状态**：前端已实施（P0-P2，2026-08-13），`pnpm build` + `pnpm run lint` 验证通过。本文档沉淀切换后的注意事项与决策记录。

---

## 背景与结论

- **现象**：侧边栏菜单看起来「写死在前端」——与数据库 `iam_menu` 无关。
- **核查结论**：侧边栏组件与数据管道都是通的，**根因是环境开关** `.env` 中 `VITE_ACCESS_MODE = frontend`，把菜单源头切到了本地写死路由 `asyncRoutes`（dashboard/system/result/exception 四模块）。此外后端模式存在「静默回退」：`get_user_menu` 失败**或返回空数组**都会回退到同一份写死列表，既造成假象，又是页面级访问控制的漏洞（无授权用户会获得本地写死路由的访问权）。

## 数据链路

```
.env(VITE_ACCESS_MODE) → useAppMode → MenuProcessor.getMenuList()
  → backend 模式: getUserMenu() → POST /rpc/get_user_menu
      → public.get_user_menu（JWT roles → iam_role_menu → iam_menu，WHERE is_active）
  → 转路由树 → beforeEach 守卫注册路由 + menuStore.setMenuList
  → art-sidebar-menu 渲染 menuStore.menuList
```

## 本次改动清单

| # | 文件 | 改动 |
| --- | --- | --- |
| P0 | `.env` | `VITE_ACCESS_MODE = frontend` → `backend` |
| P0 | `.env.example` | 模板默认值同步 `backend`，注释更新 |
| P1 | `src/router/core/MenuProcessor.ts` | `processBackendMenu`：仅 RPC **异常**回退本地路由；**空数组 = 合法的无菜单授权，不回退** |
| P1 | `src/router/guards/beforeEach.ts` | 菜单校验改为 `Array.isArray`——空数组放行（空侧边栏），仅非数组视为异常跳 500 |
| P2 | 无代码改动 | 前端模式代码**保留**作异常兜底（决策记录见文末） |

## 切换后行为变化（务必知晓）

1. **侧边栏 = 数据库菜单**（`iam_menu` 中 `is_active=true` 且当前角色已绑定），与菜单管理页所见一致。
2. 本地写死列表里的页面（用户中心/岗位/字典/租户/结果页/异常页等）**不再出现**——DB 里没有对应菜单行。需要哪页就去菜单管理页建行，菜单从此由数据库管理。
3. **目录无导航子级会被过滤**：`filterEmptyMenus` 只保留有 children 的目录。例如「只读镜像」目录若只有按钮级子行（按钮不入路由），则不出现在侧边栏——需给它补真实的菜单子行。
4. **无菜单绑定的角色**（如 `citywalk-user`）登录后是**空侧边栏 + 404 落点**——这是正确的授权语义，不是故障。
5. **首页推导**：`HOME_PAGE_PATH` 为空时，`menuStore.setMenuList` 用 `getFirstMenuPath` 取第一个数据库菜单作为首页，登录后落在首个菜单（当前即 `/system` → 首个子菜单）。
6. **改 `.env` 后必须重启 dev server**（vite 环境变量只在启动时读取）。
7. `.env` 不入库（gitignored）：CI/服务器等部署环境需各自配置 `VITE_ACCESS_MODE=backend`，新克隆仓库只需复制 `.env.example`（默认已是 backend）。

## 后端前置条件（排查清单）

| 前置条件 | 说明 |
| --- | --- |
| Logto JWT 携带 `roles` claim | `get_user_menu` 依赖 `request.jwt.claims.roles`；缺失时返回空数组 → 空侧边栏 |
| `iam_role_menu` 绑定 | 菜单需在角色管理页勾选授权（055 单表化后，新建菜单/按钮默认无人可见） |
| `is_active = true` | 树构建的硬过滤条件（两处 WHERE） |
| `component` 兜底 | DB 中 component 为空时走前端 `COMPONENT_FALLBACK_MAP`（`src/router/core/MenuProcessor.ts`：user/role/menu/dept/position/dict/tenant/login-log/audit-log/monitor 等）；**新页面要么 DB 写 component，要么扩充映射表** |
| 056 迁移联动 | `keep_alive`→`is_cache` 改名 + 删 `query` 列：前端已适配，后端迁移未跑时菜单保存会报错（RPC 不认 `p_is_cache`） |

## 回退语义（P1 决策）

| 场景                 | 行为                                                            |
| -------------------- | --------------------------------------------------------------- |
| RPC 异常（网络/500） | 回退本地 `asyncRoutes` + `console.warn`（防用户被锁死在空白页） |
| 返回空数组           | **不回退**，空侧边栏（防把写死路由当授权发放）                  |
| 401                  | axios 拦截器处理登出，不经回退路径                              |

## 日常菜单维护流程

1. 菜单管理页：创建目录/菜单/按钮（填类型、路由、组件、权限码；按钮填 api_url/api_method 成对）。
2. 角色管理页：为新菜单勾选授权。
3. 用户刷新页面即可看到（get_user_menu 实时查询）。

## 排查手册

| 现象 | 排查顺序 |
| --- | --- |
| 侧边栏空白 | ① JWT 是否带 roles claim ② 角色是否绑定菜单 ③ 菜单 `is_active` 是否为 true |
| 登录后落 404 | 首页推导失败或 DB 菜单无有效 component/无导航子级 |
| 「看起来还是写死的」 | ① 确认 `.env` 为 backend 且**已重启 dev server** ② 浏览器 console 是否有 `[MenuProcessor] 回退本地 asyncRoutes` 警告（说明 RPC 挂了） |
| 菜单保存报错 | 后端 056 迁移未跑（`p_is_cache` 参数不识别） |
| 新页面侧边栏不显示 | component 空且不在 `COMPONENT_FALLBACK_MAP`；或类型选错（button 不入路由） |

## 决策记录（P2）

- **前端模式代码保留**：`asyncRoutes`/`routeModules`/`filterMenuByRoles`/`useAppMode` 的 frontend 分支继续保留，作为 RPC 异常时的兜底（P1 回退路径依赖它们）。
- 彻底删除前端模式属架构决策，触发条件（建议）：后端菜单配置流程稳定运行数周、确认兜底价值已被错误页方案取代后，另行评审。
