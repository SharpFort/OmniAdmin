# 5. 菜单初始化 — 前端页面分类与入库方案

> 日期：2026-08-14 ｜ 关联：055 菜单权限单表化（SharpFort 模型）、056/057 菜单字段收敛、后端控制模式切换参考：[artd.pro 权限模式文档](https://www.artd.pro/docs/zh/guide/in-depth/permission.html) §后端控制模式状态：**待用户审查** → 审查通过后写入 iam_menu / iam_role_menu

## 1. 背景与目标

- 前端页面全部放入菜单管理表（`iam_menu`），切换 `VITE_ACCESS_MODE=backend`，由 `get_user_menu` 驱动侧边栏（后端控制模式）。
- 目录结构按用户拍板：
  - **只读镜像**（Logto 镜像表：users/role/tenants/user_role/user_tenants 对应页面）
  - **系统管理**（业务表对应页面 + 日志）
  - **结果页面**（开源模板自带 success/fail）
  - **异常页面**（开源模板自带 403/404/500）
  - **仪表盘**（工作台）
- 055 模型约束：
  - `directory`/`menu` 行：有 `router`/`component`，`api_code`/`api_url`/`api_method` 强制 NULL（D8/Admin.NET 语义）
  - `button` 行：有 `api_code` + `api_url`/`api_method`（成对，D6），`router`/`component` 强制 NULL
  - 一码多端点 = 多行同 `api_code` 的 button 行（如 `public:dict:create` 两行）
- 路由拼接契约（MenuProcessor `buildFullPath`）：目录行 `router` 留空，子菜单用**相对路径**（与前端 `router/modules/*.ts` 一致）；绝对路径直接透传。非一级菜单 path 以 `/` 开头会触发 `validateMenuPaths` 控制台警告。

## 5. 与现有 DB 的差异（需重建项）

现状（`SELECT ... FROM iam_menu` 实测 2026-08-14）：

| 差异点 | 现状 | 目标 |
| --- | --- | --- |
| 路由地址 | 拼音/随意值：`system/tentent`、`system/bumen`、`system/zidianleixing`、`system/userziliao`、`end`、`yichang`、`logto` | 与前端 modules 一致的相对路径（system/dept、system/tenant…） |
| 组件路径 | 大量 NULL 或 `system/tentent/index` 式旧值 | 全部显式填写真实组件路径 |
| 目录 router | `系统管理=/system`、`只读镜像=logto`、`日志管理=system/log` | 目录行 router 留空（拼接契约） |
| 挂载关系 | 部门/岗位/字典等挂在 `系统管理` 根；角色按钮挂独立 `角色菜单` menu；只读镜像缺 4 页 | 按 §3/§4 树形重建 |
| 旧行 | `角色菜单`（role/index 无对应页面）、`MenuList`（重复菜单管理） | 删除/合并 |
| 个人中心 | 无 | 新增（is_visible=false） |
| 结果/异常目录 | 已建空目录（`end`/`yichang`） | 补子页面 + 修正 router |
| 仪表盘 | 无 | 新增目录 + 工作台 |

## 6. 写入方案（审查通过后执行）

1. **清空重建**（推荐）：`TRUNCATE iam_role_menu; TRUNCATE iam_menu CASCADE;`（055 后按钮行/端点全量在本文档内，无遗漏；角色授权随后按新树重绑）
2. 逐行 `rpc_create_menu`（超管 claims 下执行）建目录→菜单→按钮，`order_num` 按 §3/§4；`route_name` 手填（Menus/ResultSuccess/Exception403 等）
3. 角色绑定：`rpc_set_role_menus('role_super_admin', <全量菜单 id>)`（超管短路其实不依赖绑定，绑全量保 casbin_rule 完整）；`tenant_admin` 绑其可见页（只读镜像全 5 页 + 系统管理业务页，不含 login-log/app-config/用户角色）
4. 前端联动（同批提交）：
   - `.env` `VITE_ACCESS_MODE=backend`（artd.pro §权限模式）
   - `MenuProcessor.ts` `COMPONENT_FALLBACK_MAP` 补 `user-center/app-config/cron-job-log/user-position/dict-data`（component 已显式填，兜底仅防御）
   - `usePermission.ts` 双通道已兼容（get_user_menu button 行）
5. 验证：`get_user_menu` 输出树形完整；页面逐项可导航；按钮 v-perm 按角色显隐
