# 搜索组件与分页跳转规范

> 制定日期：2026-08-09｜适用：OmniAdmin（art-design-pro 3.0.2 + Vue3 + Element Plus）依据：Art Design Pro 官方文档（[ArtSearchBar](https://www.artd.pro/docs/zh/guide/components/art-search-bar.html) / [useTable](https://www.artd.pro/docs/zh/guide/hooks/use-table.html)）+ 审计日志/登录日志页重构实践（浏览器实测验证）

## 1. 目标

统一所有列表页的搜索组件形态、数据流与分页跳转行为，消除「手搓搜索栏」反模式，让搜索体验一致且可维护。

## 2. 组件选型与页面结构

### 2.1 一律使用 ArtSearchBar

- 组件已全局自动注册（unplugin-vue-components），页面无需 import
- **禁止**在页面内手搓 `ElInput`/`ElSelect`/`ElDatePicker` + 按钮拼搜索栏

### 2.2 页面级包装组件（`modules/*-search.vue`）

搜索栏独立为页面同目录 `modules/xxx-search.vue` 包装组件，与页面解耦：

```vue
<!-- modules/user-search.vue（参考实现） -->
<template>
  <ArtSearchBar
    ref="searchBarRef"
    v-model="formData"
    :items="formItems"
    :rules="rules"
    :span="8"
    :is-expand="true"
    @reset="handleReset"
    @search="handleSearch"
  />
</template>

<script setup lang="ts">
  interface Props {
    modelValue: { query: string; status: string }
  }
  interface Emits {
    (e: 'update:modelValue', value: any): void
    (e: 'search', params: any): void
    (e: 'reset'): void
  }
  const props = defineProps<Props>()
  const emit = defineEmits<Emits>()
  const searchBarRef = ref()
  const formData = computed({
    get: () => props.modelValue,
    set: (val) => emit('update:modelValue', val)
  })
  const formItems = computed(() => [
    { label: '用户名', key: 'query', type: 'input', placeholder: '请输入用户名', clearable: true }
    // select 选项：静态常量或 onMounted 异步加载（如用户/部门下拉）
  ])
  function handleReset() {
    emit('reset')
  }
  async function handleSearch(params: any) {
    await searchBarRef.value.validate()
    emit('search', params) // params 已由 ArtSearchBar 清洗（空串/空数组已剔除）
  }
</script>
```

页面侧使用：

```vue
<XxxSearch v-model="searchForm" @search="handleSearch" @reset="resetSearch" />
```

## 3. 布局约定

| 表单项数量 | span                        | 布局                                    |
| ---------- | --------------------------- | --------------------------------------- |
| ≤ 3        | 默认 6                      | 单行（按钮列同排）                      |
| > 3        | **8** + `:is-expand="true"` | **两行**（每行 3 项，按钮列第二行右侧） |

- `is-expand=true`：全部表单项默认可见，**无「展开/收起」按钮**（收起态只显示每行数量-1 项，容易让用户漏掉条件）
- 参考实现：`audit-log-search.vue`（4 项两行）、`login-log-search.vue`（3 项一行）

## 4. 数据流与分页跳转规则（核心）

页面侧统一模式（参考 `audit-log/index.vue`、`login-log/index.vue`、`user/index.vue`）：

```ts
// 单一数据源：搜索/重置/分页均基于此；ArtSearchBar 空值自动剔除
const defaultSearchForm = () => ({ query: '', status: '' })
const searchForm = ref(defaultSearchForm())

// 搜索 → 合并清洗后参数 + 跳回第 1 页
const handleSearch = (params: any) => {
  Object.assign(searchForm.value, defaultSearchForm(), params)
  pagination.current = 1
  getData()
}
// 重置 → 恢复默认条件 + 跳回第 1 页
const resetSearch = () => {
  searchForm.value = defaultSearchForm()
  pagination.current = 1
  getData()
}
const handleSizeChange = (size: number) => {
  pagination.size = size
  pagination.current = 1
  getData()
}
const handleCurrentChange = (page: number) => {
  pagination.current = page
  getData()
} // 翻页保留条件
```

**跳转规则速查**：

| 操作                       | 页码行为                                         |
| -------------------------- | ------------------------------------------------ |
| 搜索 / 重置 / 修改每页条数 | → 第 1 页                                        |
| 翻页                       | 保持当前搜索条件                                 |
| 新增数据后刷新             | → 第 1 页（`refreshCreate` 语义）                |
| 编辑数据后刷新             | 保持当前页（`refreshUpdate` 语义）               |
| 删除数据后刷新             | 若当前页删空则回退上一页（`refreshRemove` 语义） |

## 5. 时间范围约定（⚠️ 时区坑）

### 5.1 组件写法（关键坑）

ArtSearchBar 的 `type` 只用于选择组件，**具体模式必须写在 `props.type` 里**：

```ts
{
  label: '时间范围',
  key: 'date_range',
  type: 'datetime',            // 映射 ElDatePicker
  props: {
    type: 'daterange',         // ← 必须写这里！只写顶层 type:'daterange' 会退化为单日期选择
    startPlaceholder: '开始日期',
    endPlaceholder: '结束日期',
    rangeSeparator: '至',
    valueFormat: 'YYYY-MM-DD'  // date-only（按天粒度足够）
  }
}
```

> 实测教训：顶层 `type: 'daterange'` 时 ElDatePicker 收不到 type prop，退化为单日期选择，选两次日期只剩一个值 → 查询空结果。

### 5.2 参数转换（统一走 `src/utils/date.ts` 的 `toIsoLocal`）

- date-only 范围 → 结束日自动补 `23:59:59`（当天闭区间，左闭右闭）
- **必须先补时间再 `new Date`**：ISO date-only（`"YYYY-MM-DD"`）按 **UTC** 解析，与按本地时区解析的结束时间混用会造成 **8 小时偏移**（UTC+8 环境漏掉凌晨 00:00~08:00 段）
  - 实测：选「08-09 ~ 08-09」若直接 `new Date("2026-08-09")` → 范围变 [08:00, 次日 07:59]，凌晨登录记录查不到
- API 层统一转换，调用方只传本地时间字符串：
  ```ts
  p_start_date: toIsoLocal(params.start_date),        // date-only 补 00:00:00
  p_end_date: toIsoLocal(params.end_date, true),      // date-only 补 23:59:59
  ```

## 6. 后端 RPC 参数约定

- 参数名 `p_xxx` 与后端 `pg_get_function_arguments` 逐一对应（**命名即契约**）
- 空值传 `null`（后端 `p_x IS NULL` 短路）；分页 `p_limit`/`p_offset`（上限 100，035 统一）
- snake_case 透传，零转换层（§2.3 定稿）
- 搜索类语义：关键词 → ILIKE 多字段（如审计 `p_query` 匹配操作人+变更内容）；表名 → 模糊 ILIKE（036 起）

## 7. 已知坑清单

1. **ArtSearchBar daterange 写法**：见 §5.1（顶层 type 不传 props 给 ElDatePicker）
2. **时区偏移**：见 §5.2（date-only 必须先补时间再解析）
3. **`$t` 缺失 key 返回 key 字符串**（truthy）——`$t(k) || 'fallback'` 永不兜底，直接硬编码或补语言包
4. **`el-tab-pane` 内组件**：若页面被 keep-alive 缓存，子组件 `onMounted` 只在首次挂载执行；需要每次切 tab 刷新时用 `@tab-change` + 组件 `defineExpose` 显式触发（参考 audit-log 时间线）
5. **用户/部门下拉数据源**：`getUserList`/`getDeptTree` 在 `*-search.vue` 的 `onMounted` 异步加载，`filterable` 开启

## 8. 审计日志分类字段核实结论（2026-08-09 实测）

**不加分类搜索项**。`audit_log` 表 24 列实测：019 扩展列（`module`/`action`/`target_type`/`target_id`/`result`/`ip`/`region`/`duration_ms`/`user_agent`）**全部无数据**（0/43 非空）；`log_type` 恒 `data_change`、`source` 恒 `trigger`——加筛选项必为空。且 `v_audit_log_detail` 视图未投影这些列。若未来审计链路写入扩展列，需先扩展视图 + RPC 参数（036 结构已预留），再加搜索项。
